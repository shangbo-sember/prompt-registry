# 版本与状态规则

## 一、编号

- prompt ID：`PRM-IMG-<三位序号>`，全仓库唯一。**删掉的 prompt 也不回收序号**，避免历史记录指向错乱。
- 版本目录：`versions/v1.md`、`v2.md`……**从 v1 开始连续递增**，不允许跳号、不允许补号。
- 文件名 slug：小写连字符，与 `meta.yaml` 的 `slug` 一致，与目录名一致。

## 二、版本

1. **每次实质改动都升版**。改一个词也算升版——因为出图结果会变，迭代史的意义就在于能回到"哪一版出了什么图"。
2. **旧版本永不覆盖**。任何对 `versions/vN.md` 的历史内容修改都视为违规，CI 会拦。
3. 每个新版本必须写 **「相对上一版改动」**：改了什么、为什么改。写"优化一下"不算。
4. 同一 prompt **连续迭代超过 3 版仍不达预期**，先停下来：换风格方向、换参考图，或换图片来源。不要继续机械重生成。

## 三、状态（单向流转）

```
候选 ──→ 选中
  └───→ 弃用（必须写弃用原因）
```

- **弃用必须填 `deprecated_reason`**，写清是哪里不达标（构图 / 文字渲染 / 风格偏离 / 禁忌命中）。
- **已「选中」的版本不能静默改回「候选」**。确需回退，新开一版并在改动说明里写清原因，旧版保留为历史。
- 状态记在**版本文件**上（`versions/vN.md` 的 frontmatter），`meta.yaml` 里记 `status` 表示"当前生效版的状态"。

## 四、来源

prompt 本身不带来源，但用 prompt 产出的图入库必须能说清来源，仅限三类：

- AI生图
- 合规图库
- 品牌实拍·产品图

说不清来源或无法确认授权的图，不入库。仓库里如果在 prompt 里引用了参考图，必须在该版本的「参考素材」写明出处与授权状态。

## 五、生效

- `main` 分支上 `meta.yaml` 的 `current_version` 指向哪一版，哪一版就是生效版本。
- `prompt.md` 必须与 `current_version` 同步，由 `scripts/new_version.py` 自动更新，不要手改。

## 六、什么该进仓库，什么不该

| 进 | 不进 |
| --- | --- |
| prompt 正文、改动说明、弃用原因 | 生成的图片文件（放飞书台账 / 云盘） |
| 断言用例与回归结论 | 平台账号、API Key、密钥 |
| 尺寸、比例、用途、关联内容 ID | 客户敏感信息、未获授权的参考图原图 |
